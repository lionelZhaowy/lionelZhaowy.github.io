## Project Background
In foggy or hazy environments, cameras suffer from reduced visibility because the turbid medium attenuates scene-reflected light and introduces atmospheric light. This severely degrades image quality and impairs subsequent image processing in systems like urban surveillance and satellite remote sensing. Recently, deep learning-based dehazing algorithms have delivered impressive performance due to their end-to-end automated feature extraction capabilities. However, their vast parameter sizes and high computational complexity prevent practical deployment on edge devices with strict power and cost limitations.

This project adopted a **hardware-software co-design** approach to build a highly energy-efficient, real-time video dehazing system based on the low-cost PYNQ-Z2 (Zynq-7020) platform. On the algorithm side, we implemented network pruning and quantization compression. On the hardware side, we customized a deep learning accelerator featuring inter-layer parallelism, exploiting the pipeline-level parallel processing capabilities of FPGAs to overcome computational bottlenecks.

<details class="tech-accordion" markdown="1">
  <summary>1. Algorithmic Light-weighting: Pruning and Quantization of AOD-Net</summary>
  <div class="tech-accordion-content" markdown="1">

The target hardware, the xc7z020 chip, has very limited on-chip BRAM resources. The original AOD-Net architecture contains numerous branching paths, which would force the accelerator to cache large-scale feature maps either on-chip or off-chip for extended periods, creating an unacceptable storage overhead. After a comprehensive evaluation, I implemented the following optimization strategies:
* **Network Pruning:** Eliminated the Concat nodes that required the longest cross-layer staging times and consumed the most memory.
* **INT8 QAT:** Introduced Quantization-Aware Training to compress the model from floating-point precision down to INT8.
  
The optimized lightweight network structure is shown in Figure 1, reducing the model parameter size to just **1.61 kB**. Evaluated on the RESIDE dataset, the optimized model retained excellent dehazing performance, achieving an SSIM of 0.872 and a PSNR of 22.79 dB.

<details class="tech-accordion" markdown="1">
  <summary>2. Hardware Microarchitecture Design: Inter-Layer Pipelined Parallel Accelerator IP</summary>
  <div class="tech-accordion-content" markdown="1">

To maximize throughput, the accelerator utilizes an inter-layer pipelined architecture (as shown in Figure 2). A dedicated computing module is customized for each convolutional layer. As soon as a preceding layer outputs a partial set of valid data, the subsequent layer can immediately initiate its computation, drastically reducing the idle waiting time of the execution units.

<div align="center">
    <img src="/images/project/202305-202309-MicroHFUT/AODNet_IP.png" width="80%" alt="Figure 2">
    <br>
    <div style="color: #666; font-size: 14px; padding-top: 5px;">
        <b>Figure 2.</b> Overall Architecture of the Hardware Accelerator IP
    </div>
</div>

For the computing array, we applied parallel optimization strategies including **Input Stationary (IS)** dataflow and **Loop Unrolling**. Input features reside in the Input Buffer, while the multiply-accumulate (MAC) units iterate through the Weight RF to perform calculations. The generated intermediate partial sums are accumulated via an adder tree structure and written into the Output Buffer (the IS dataflow demonstration is detailed in Figure 3). For the accumulated INT32 results, the hardware features built-in MAC-shift and ReLU activation logic before re-quantizing them back into INT8 outputs (the core PE microarchitecture is illustrated in Figure 4).

Additionally, to enhance data reuse efficiency, we employed a **Line Buffer** strategy (as shown in Figure 5). When the convolution kernel's sliding window moves down, only a single newly scanned row of pixels needs to be loaded into the buffer. Hardware-level data interleaving logic ensures correct data arrangement, pushing data reuse efficiency to its theoretical limit.

<details class="tech-accordion" markdown="1">
  <summary>3. System-Level Integration: PYNQ-Based End-to-End Video Stream</summary>
  <div class="tech-accordion-content" markdown="1">

Leveraging the PYNQ framework's capability to automatically map underlying PL (Programmable Logic) resources to the upper-level Linux user space, I constructed a complete "data acquisition - AI inference - image display" video pipeline (architecture in Figure 6, Block Design in Figure 7):
* The customized AOD-Net acceleration engine was encapsulated into an IP with a standard AXI-Stream interface, with data movement orchestrated by a DMA controller.
* Based on the Atmospheric Scattering Model (ASM), the image post-processing logic required for dehazing was also encapsulated into a hardware IP and connected to the DMA. This offloaded intensive tasks from the CPU and enabled true end-to-end inference.

To visually validate the acceleration performance, I set up a dual-system hardware comparison demonstration environment (Figure 8). It consists of two PYNQ-Z2 boards, two displays, one USB camera, one HDMI splitter, and a host PC. One of the PYNQ boards drives the USB camera to capture images and outputs the HDMI signal. After passing through the splitter, one stream goes directly to the left display to show the original image, while the other stream is routed to the second PYNQ board for dehazing. The final processed result is output to the right display via HDMI.

## Reflections and Summary
### Personal Evaluation: From Theory to Practice
This project marked the first time I successfully completed a full hardware-software co-design flow—stretching from algorithmic compression down to underlying hardware customization. By deploying an algorithmic light-weighting strategy and an inter-layer parallel hardware pipeline, we squeezed an otherwise massive neural network model into a highly resource-constrained Zynq chip.

However, during development, I also came to realize the limitations of fully customized designs. The datapath and computing array were strictly tailored for a single algorithm; if the algorithm iterates, the entire IP must be redesigned from scratch. This lack of flexibility provided a compelling catalyst for my subsequent transition into exploring Domain-Specific Architectures (DSA) and programmable AI chips.

### AI Systems: The Constraints of Amdahl's Law
As summarized in my [National IC Innovation Competition Project]({{ '/projects/202303-202308-awcloud/#Amdahl' | relative_url }}), the overall performance of an AI inference system is bound by Amdahl's Law, and this project was no exception.

**Bottleneck Analysis and Solutions:**
The culprit behind this discrepancy is the Python runtime environment upon which the PYNQ framework relies. The ARM core introduces catastrophic serial software overhead when calling PIL/OpenCV libraries for image preprocessing, format conversion, and cross-state data stitching. PYNQ sacrifices execution efficiency for immense development convenience at the application layer, which inadvertently bottlenecks the excellent computational performance of the underlying FPGA.

To thoroughly break this deadlock, the system architecture must be refactored:
1. **Lowering the Software Layer:** Abandon the inefficient Python ecosystem and refactor the application layer using a combination of C++ and OpenCV, accelerating the preprocessing stage via multi-threading or NEON instruction sets.
2. **Constructing a Pure PL Video Stream:** Offload image cropping, scaling, and format assembly entirely to the FPGA (PL side). Utilize VDMA to construct a pure hardware datapath that bypasses CPU memory copying, allowing data to remain parallelized entirely within the PL.

This project further cemented my understanding that achieving system-level optimization requires rigorous focus on data movement and protocol translation.

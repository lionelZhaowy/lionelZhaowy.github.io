## Project Background
In foggy or hazy environments, suspended particles attenuate scene radiance while atmospheric light is scattered toward the camera, reducing image contrast and visibility. This degradation can substantially impair downstream processing in applications such as urban surveillance and remote sensing. Deep neural networks have achieved strong image-dehazing performance through end-to-end feature learning, but their memory and computational requirements often preclude deployment on edge devices with stringent power and cost constraints.

This project adopted a **hardware–software co-design** methodology to build an energy-efficient real-time video dehazing system on the low-cost PYNQ-Z2 (Zynq-7020) platform. The network was simplified and quantized at the algorithm level, while a custom inter-layer-pipelined accelerator exploited FPGA spatial parallelism to meet the required throughput.

<details class="tech-accordion" markdown="1">
  <summary>1. Model Compression: Simplification and Quantization of AOD-Net</summary>
  <div class="tech-accordion-content" markdown="1">

The target XC7Z020 device provides limited on-chip BRAM. The original AOD-Net contains several branches whose long-lived intermediate feature maps would incur unacceptable on-chip or off-chip storage overhead. I therefore applied two model-level optimizations:
* **Architecture simplification:** Removed the `Concat` paths with the longest feature lifetimes and largest memory footprint.
* **INT8 QAT:** Applied quantization-aware training to convert the floating-point model to INT8 inference.
  
The resulting compact architecture is shown in Figure 1. Its parameters occupy only **1.61 kB**, while evaluation on RESIDE yields an SSIM of 0.872 and a PSNR of 22.79 dB.

<details class="tech-accordion" markdown="1">
  <summary>2. Hardware Microarchitecture Design: Inter-Layer Pipelined Parallel Accelerator IP</summary>
  <div class="tech-accordion-content" markdown="1">

To maximize throughput, the accelerator adopts the inter-layer pipeline shown in Figure 2. Each convolutional layer is implemented as a dedicated compute stage; once an upstream stage produces valid data, the downstream stage can begin processing immediately. This streaming schedule minimizes idle time between layers.

<div align="center">
    <picture class="optimized-media"><source srcset="/images/project/202305-202309-MicroHFUT/AODNet_IP.webp" type="image/webp"><img src="/images/project/202305-202309-MicroHFUT/AODNet_IP.png" width="80%" alt="Figure 2" loading="lazy" decoding="async"></picture>
    <br>
    <div style="color: #666; font-size: 14px; padding-top: 5px;">
        <b>Figure 2.</b> Overall Architecture of the Hardware Accelerator IP
    </div>
</div>

The compute array combines an **input-stationary (IS)** dataflow with **loop unrolling**. Input activations remain in the input buffer while multiply–accumulate units iterate over the weight register file; an adder tree reduces the resulting partial sums before they are written to the output buffer (Figure 3). The PE datapath then applies multiplication, shifting, and ReLU to the accumulated INT32 values before requantizing them to INT8 (Figure 4).

A **line-buffering** scheme further increases spatial reuse (Figure 5). When the convolution window advances vertically, only the newly exposed image row is loaded; hardware interleaving preserves the required window layout and avoids reloading previously buffered pixels.

## Reflections and Summary
### Personal Evaluation: From Theory to Practice
This project was my first complete hardware–software co-design effort, spanning model compression, custom datapath design, RTL implementation, and system integration. Combining a compact network with an inter-layer hardware pipeline enabled deployment on a severely resource-constrained Zynq device.

It also exposed the limitations of fully specialized hardware. Because the datapath and compute array were tailored to one network, a substantial model revision could require a complete IP redesign. This lack of programmability motivated my later work on domain-specific architectures (DSAs) and programmable AI processors.

### AI Systems: The Constraints of Amdahl's Law
As summarized in my [National IC Innovation Competition Project]({{ '/projects/202303-202308-awcloud/#Amdahl' | relative_url }}), the overall performance of an AI inference system is bound by Amdahl's Law, and this project was no exception.

**Bottleneck Analysis and Solutions:**
The dominant overhead arose in the Python-based PYNQ software path. Image preprocessing, format conversion, and data assembly through PIL and OpenCV executed serially on the ARM core, masking the performance of the FPGA kernels. PYNQ greatly simplified application development, but this software convenience came at a substantial end-to-end latency cost.

To thoroughly break this deadlock, the system architecture must be refactored:
1. **Move the application path to native code:** Reimplement preprocessing in C++ and OpenCV, using multithreading and ARM NEON where appropriate.
2. **Construct a PL-only video pipeline:** Offload cropping, resizing, and data-layout conversion to the FPGA and use VDMA to eliminate CPU-mediated frame copies.

This project further cemented my understanding that achieving system-level optimization requires rigorous focus on data movement and protocol translation.

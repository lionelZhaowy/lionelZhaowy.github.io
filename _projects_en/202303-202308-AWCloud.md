## Project Background
This project was a competition track for the 2023 National College Student Integrated Circuit Innovation and Entrepreneurship Competition (NICIEC - AWCloud Cup), focusing on automated defect detection in industrial aluminum can/sheet production lines. The organizers provided a specific dataset, an Intel Cyclone V SoC-based cloud FPGA platform (AWCloud), and a complementary AI inference accelerator demo alongside its toolchain.

The dataset comprises four common defect types found in aluminum products:
- zhen_kong (Pinhole)
- ca_shang (Scratch)
- zang_wu (Dirt/Stain)
- zhe_zhou (Crease/Wrinkle)

## Deployment and Performance
Through algorithm-level joint compression, we achieved a significant increase in inference speed while ensuring high detection accuracy. The specific performance comparison metrics are detailed in the table below:

| Metric Dimension | Pre-Optimization (Baseline FP32) | Post-Optimization (FPGM Pruning + INT8 Quantization) | Net Gain |
| :--- | :--- | :--- | :--- |
| **Detection Accuracy (mAP)** | 98.45% | 97.05% | Accuracy dropped marginally by 1.4% |
| **Parameter Scale** | 100% | 87% | Pruned 13% of redundant parameters |
| **Pure Inference Latency** | 473 ms | 170 ms | Computation accelerated by 2.78x |
| **End-to-End Latency** | 540 ms | 235 ms | **Overall frame rate boosted by 2.3x** |

The actual inference performance is demonstrated in Figure 6. For input RGB images with a resolution of 300×300, the system stably and accurately outputs bounding boxes for aluminum surface defects, successfully balancing algorithmic accuracy with the real-time requirements of edge deployment.

## Reflections and Summary
### Personal Evaluation: From Theory to Practice
This project was a concrete attempt to put the "joint optimization theory of compression algorithms"—explored in the [CAS Innovation Training Program]({{ '/projects/202207-202307-semi/#semi_tag' | relative_url }})—into practice. During implementation, I discovered that because depthwise separable convolutions are inherently highly streamlined, they are extremely sensitive to pruning operations. Consequently, this approach could only safely eliminate 13% of the parameters; exceeding this threshold would trigger a severe accuracy collapse. Furthermore, the provided accelerator demo only supported coarse-grained per-tensor quantization, which easily compromised accuracy given the significant variance in data distributions across different channels in DW convolutions. To mitigate this shortcoming, I adopted a Quantization-Aware Training (QAT) approach, successfully recovering the accuracy loss through fine-tuning.

Somewhat regrettably, constrained by the competition timeline, I was unable to deeply reconstruct the hardware accelerator layer of the demo. Bottlenecks in hardware execution efficiency directly bottlenecked the final frame rate. However, this experience laid the solid groundwork for my subsequent in-depth research into underlying hardware accelerator architectures.

### AI Systems: The Constraints of Amdahl's Law
The actual inference efficiency of an AI system is not solely dictated by the theoretical computational complexity and parameter count of the algorithm; the real-world execution efficiency of the underlying hardware is often the limiting factor (the "short board of the barrel"). From a system architecture perspective, overall performance is inevitably bounded by Amdahl's Law—meaning the system's maximum speedup ultimately depends on its most time-consuming serial or inefficient task. Therefore, the key to breaking through system bottlenecks lies in optimizing the weakest link.

This law was intuitively verified in the project's accelerator demo: using the ARM core for tensor data rearrangement from HWC to CHW format via serial loop iterations caused the compute array to sit idle, severely dragging down computational efficiency. To address this bottleneck, solutions can be approached from both software and hardware perspectives:
- *Software Parallelization:* Introduce the ARM NEON instruction set to vectorize and accelerate the rearrangement process using SIMD technology.
- *Custom Hardware Rearrangement:* Design a custom data rearrangement module on the FPGA side, utilizing hardware pipelining to offload the burden from the ARM core.

This issue of data movement throttling computation is not unique to the demo; it is a ubiquitous pain point currently facing AI chips. With the advent of the LLM era, where model parameter counts and context dimensions are growing exponentially, this constraint has become even more pronounced. The research focus for AI accelerators has gradually shifted from the early-stage race for peak compute array performance towards optimizing External Memory Access (EMA) and on-chip data reuse efficiency. How to prevent compute arrays from stalling due to data starvation has now emerged as the central thesis in modern AI system design.
